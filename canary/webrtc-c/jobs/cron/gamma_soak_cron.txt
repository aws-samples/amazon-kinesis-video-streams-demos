# Continuous soak canary cron entry, GAMMA.
#
# This is the gamma twin of soak_cron.txt. Read that file first -- everything it
# says about the soak being a RESTARTER rather than a scheduler, about what the
# tick can and cannot recover, and about the H/30 interval trade-off applies here
# unchanged and is not repeated. What follows is only what DIFFERS for gamma, and
# why each parameter is present or absent.
#
# DO NOT COPY soak_cron.txt's LINE. It is aimed at prod us-east-1 with no ENDPOINT
# and it sets six parameters that are either wrong for gamma or redundant against
# gamma_runner.groovy's own defaults. The two runners have different defaults, and
# that is the whole reason this is a separate file.
#
# ---------------------------------------------------------------------------
# BEFORE THIS ENTRY CAN DO ANYTHING
#
#   1. Re-seed the gamma job from twcc-canary's gamma_runner.groovy and let ONE
#      build run. Jenkins only materializes a parameter after the updated
#      pipeline definition has executed once; until then every name below is
#      silently discarded and the job runs on its stored defaults. This is the
#      single most common way a cron edit appears to do nothing.
#   2. Signaling channel AND KVS stream, both named "${JOB_NAME}-GammaRpiSoak",
#      plus UpdateMediaStorageConfiguration associating them. Without the
#      association the master connects, nothing persists, and the consumer sits
#      on an empty stream reporting availability=0 -- a green-looking failure.
#      Set data retention on the stream: this ingests continuously.
#   3. TWCC shadow-mode allowlist for account 232283333863 in **us-west-2**. The
#      existing allowlisting is us-east-1. Not needed for the soak to run, but
#      needed before any TWCC number from gamma means anything. Longest lead
#      time of anything on this list -- start it first.
#   4. Consumer node instance profile trusted by Canary-STS. SOAK_MODE implies
#      CONSUMER_AUTO_REFRESH_CREDS, which re-assumes CANARY_STS_ROLE_ARN using
#      the node's instance profile as base credentials. Fails closed.
#   5. Three DEDICATED nodes. The soak holds one executor forever; sharing with
#      the periodic gamma jobs makes those queue indefinitely, which is the
#      gamma-pileup failure mode already seen once. The master node also needs
#      its own label because framesrc flips ~/webrtc-c-storage-master/build/
#      .build-flags to gst=ON, and alternating with a disk-mode job forces a
#      full rebuild every single run.
#   6. Cleanup crons on all three nodes (cleanup-master.sh, cleanup-viewer.sh,
#      cleanup-consumer.sh, cleanup-common.sh). A soak node without them fills
#      its disk.
#
# ---------------------------------------------------------------------------
# EVERY PARAMETER, AND WHY
#
# SET, and would be WRONG on the default:
#   SCENARIO_LABEL=GammaRpiSoak   The consumer's switch is a closed allowlist and
#                                 an unknown label makes it THROW AND DIE
#                                 (WebrtcStorageCanaryConsumer.java, `default:`).
#                                 GammaRpiSoak is past that allowlist as of the
#                                 commit that adds CanaryConstants.GAMMA_SOAK_LABEL
#                                 -- if the consumer dies immediately on an
#                                 "Improper canary label" error, the deployed jar
#                                 predates it. This must NOT be RpiSoak: the
#                                 consumer ignores METRIC_SUFFIX entirely, so the
#                                 label is its ONLY gamma/prod separation, and
#                                 reusing RpiSoak would merge gamma's 24/7
#                                 datapoints into the aggregate the prod soak
#                                 alarms on -- alarms already tuned to tolerate
#                                 exactly 10 availability=0 events per day from
#                                 ONE soak's by-design hourly reconnect.
#   RUNNER_LABEL=GammaRpiSoak     Names the channel and stream, and is the
#                                 master's metric dimension. Must not collide
#                                 with any other entry on this job.
#   SOAK_MODE=true                Default false. The master switch: master runs
#                                 sampleDuration=0, consumer goes continuous and
#                                 gets auto-refreshing creds, viewer recycles in
#                                 a while(true), and the runner's timeouts lift.
#   JS_STORAGE_VIEWER_JOIN=true   Default false. No viewer without it.
#   VIDEO_VERIFY_ENABLED=true     Default false. Enables the consumer's periodic
#                                 GetClip + verify.py verification.
#   CANARY_MEDIA_SOURCE=framesrc  Default empty (= disk, no GStreamer). framesrc
#                                 is the ONLY non-disk source that both loops
#                                 forever and carries the burned-in frame counter
#                                 that SSIM verification needs. filesrc ends at
#                                 EOF and would quietly measure only the file's
#                                 length (GstMedia.cpp:547); testsrc/devicesrc
#                                 loop but have no counter, so verification
#                                 degrades to presence-only (see the
#                                 CANARY_VERIFY_MODE selection in the runner).
#   VIEWER_WAIT_MINUTES=120       Default 20 -- too short. The master's first
#                                 build on a fresh node is a gst=ON build from
#                                 scratch, and the viewer gives up waiting.
#   METRIC_SUFFIX=-gamma-soak     Default '-gamma', which is not wrong so much as
#                                 not specific enough: the periodic gamma jobs
#                                 also carry '-gamma', so leaving it would merge
#                                 this soak's hourly-reconnect zeros into the
#                                 gamma periodic alarms -- the same mistake as
#                                 reusing RpiSoak, one layer out. Note the suffix
#                                 reaches the JS VIEWER ONLY; the master emits
#                                 unsuffixed names (separated by RUNNER_LABEL) and
#                                 the consumer ignores it (separated by
#                                 SCENARIO_LABEL). All three are separated, by
#                                 three different mechanisms.
#   GIT_HASH=twcc-canary          Default 'metric-implementation'. Everything the
#                                 soak needs -- SOAK_MODE, framesrc/GstMedia,
#                                 SoakStreamVerifier, the consumer's CloudWatch
#                                 appender -- exists only on twcc-canary.
#   ENDPOINT=...                  Default empty = the PROD control plane. Leaving
#                                 it empty is the failure this file exists to
#                                 prevent: the run goes green while testing prod,
#                                 and only METRIC_SUFFIX suggests otherwise. This
#                                 is exactly what the 11h 2026-09-08 soak did.
#
# SET, and node-dependent -- these three assume a Raspberry Pi master, matching
# the prod soak. If the gamma soak master is an EC2 instance instead, DELETE all
# three: EC2 nodes are not role-chained, so STS_DURATION_SECONDS falls back to
# its 43200 default and the IoT credential provider is unnecessary.
#   USE_IOT_CREDENTIALS=true      A Pi's IoT-certificate base credentials cap
#                                 role-chained STS sessions at 1 hour. Without
#                                 the auto-refreshing IoT provider the master
#                                 dies ~1h into the soak.
#   IOT_CORE_THING_NAME=...       REQUIRED when USE_IOT_CREDENTIALS=true, differs
#                                 per Pi, and must match that node's
#                                 ~/.aws-iot/credhelper.sh thing. The other three
#                                 IOT_CORE_* parameters have working defaults.
#   STS_DURATION_SECONDS=3600     Default 43200, which a role-chained Pi cannot
#                                 mint. Must stay ABOVE the viewer's fixed 2400s
#                                 recycle interval; 3600 leaves 1200s of margin.
#
# OMITTED because gamma_runner.groovy's default is already correct -- setting
# these would only create a second place to keep in sync:
#   AWS_DEFAULT_REGION            default 'us-west-2'. (soak_cron.txt sets
#                                 us-east-1; that is a prod-only value.)
#   LOG_GROUP_NAME                default 'WebrtcSDK'. Now carries three streams
#                                 per run -- master, viewer and consumer -- so
#                                 confirm the group's retention is set before a
#                                 24/7 producer starts writing to it.
#   MASTER_NODE_LABEL etc.        defaults are already gamma-* -- but see the
#                                 dedication requirement above; if a dedicated
#                                 node does not carry the default label, these
#                                 must be set explicitly.
#
# OMITTED because they do nothing here -- do not "helpfully" add them back:
#   DURATION_IN_SECONDS           All three components ignore it under SOAK_MODE.
#                                 Its 156 default is read only by the non-soak
#                                 branch of the timeout ternaries.
#   VIEWER_SESSION_RECYCLE_SECONDS  Not a declared parameter in either runner
#                                 (only read as `params.X ?: '2400'`), so setting
#                                 it here has no effect. The interval is fixed at
#                                 2400s.
#   CONSUMER_CONTINUOUS,          Both implied by SOAK_MODE in the runner.
#   CONSUMER_AUTO_REFRESH_CREDS
#   IOT_CORE_CREDENTIAL_ENDPOINT  Its us-west-2 default is correct here, and is
#                                 account-scoped rather than region-bound anyway.
#   RESCHEDULE                    Defaults false and must stay false: the
#                                 rescheduleParams list is still missing 18
#                                 parameters including SOAK_MODE itself, so a
#                                 reschedule would silently restart this as a
#                                 BOUNDED run after already reporting
#                                 SoakRestarted=1.
#
# ---------------------------------------------------------------------------
# Three values below are placeholders and the entry will misbehave until each is
# replaced. Nothing here can guess them:
#   REPLACE-WITH-GAMMA-CONTROL-PLANE-URI  the gamma control plane
#   gamma-rpi5-soak / ...-viewer / ...-consumer  the three dedicated node labels
#   REPLACE-WITH-SOAK-PI_thing            the master Pi's IoT thing name
#
